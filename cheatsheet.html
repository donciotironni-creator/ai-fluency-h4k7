Cheatsheet — Claude Code

comenzi arbori de decizie model/effort permisiuni

Pagina pe care o ții deschisă zilnic. Adună într-un singur loc referințele și arborii de decizie pe care cursul îi predă împrăștiat prin sesiuni — comenzi, plan mode, model/effort, CLAUDE.md vs skill, /clear, permisiuni.

Sintaxa se schimbă, principiile rezistă. Claude Code publică des — comenzile, flag-urile și shortcut-urile de mai jos reflectă versiunea curentă. La începutul fiecărei sesiuni rulează /help și confirmă. Ce e marcat „de confirmat cu /help" e cel mai probabil să difere de la o versiune la alta.

Comenzile tale (slash commands / skills)

Comenzile custom și skills-urile s-au unificat — ambele se invocă /nume, numele vine din numele fișierului/folderului. Un skill se poate declanșa și automat de Claude (prin description). Exemple tipice pe care le construiești în S3:

/commitcommit în formatul echipei — acțiune cu efect, deci disable-model-invocation: true
/reviewreview pe diff-ul curent după convențiile repo-ului
/prdeschide un PR cu template-ul echipei

Numele comenzilor de mai sus sunt exemple din curs, nu comenzi built-in.

Plan mode vs. execuție directă

Întrebarea: atingi cod unde o surpriză te-ar costa? Comuți modurile cu Shift+Tab (de confirmat cu /help).

→ Plan mode
  • task cu ramificații / mai mulți pași
  • refactorizări
  • orice cod unde nu vrei surprize
  • primul slice pe greenfield (planul e plin de presupuneri — citește-le)
→ Execuție directă
  • editări mici, evidente
  • lookups, o singură modificare clară
  • unde planul ar fi doar overhead
Plan mode declanșează des un subagent „Explore" care scanează repo-ul și întoarce o hartă, ținând sesiunea principală curată. Citește planul înainte să aprobi și ajustează măcar o presupunere.

Comenzile: /model și /effort. Numele exacte ale modelelor se schimbă; principiul „potrivește puterea la sarcină" rămâne. Anti-tipar: Opus la orice — scump și inutil pentru explorare.

Fapt → CLAUDE.md  ·  Procedură → skill

Un singur criteriu, repetat: e un fapt stabil despre repo, sau o procedură pe care o repeți?

Fapt → CLAUDE.md

„așa e proiectul" — stabil, adevărat mereu.

  • „stack-ul e React + Vite + TS"
  • „testele rulează cu dotnet test"
  • „nu atinge RemainingDays fără review"

Se citește la fiecare sesiune → costă context mereu.

Procedură → skill

„pași de urmat" — o repeți de 2-3 ori.

  • „când review-uiesc un diff, fac pașii ăștia patru"
  • „când scriu un commit, urmez formatul ăsta"
  • „când deschid un PR, folosesc template-ul"

Se încarcă doar când o folosești → reference-ul lung costă aproape nimic până ai nevoie.

Semnul că ai greșit stratul: o secțiune din CLAUDE.md care sună a „pași de urmat", nu a „așa e proiectul" — aia voia să fie skill.

Când NU faci skill: e un fapt (→ CLAUDE.md); l-ai făcut o singură dată și n-ai motiv să-l repeți (→ doar un prompt); e ceva ce Claude face oricum bine fără instrucțiuni (→ doar adaugi zgomot).

Când dau /clear

Regula: o sesiune = un fir de gândire. Task nou → context nou.

  • /clear când treci la un task nesuspect de cel anterior.
  • /clear între pașii de bootstrap diferiți (ex: bootstrap API, apoi bootstrap front-end) — instalările umplu contextul cu zgomot.
  • Fereastra de context nu e infinită și nu e gratuită: cu cât o umpli cu log-uri lungi și istoric vechi, cu atât modelul raționează mai prost și mai scump.
Compaction comprimă istoricul când te apropii de limită — dar pierzi din detaliu. Mai bine /clear deliberat între task-uri decât să lași istoricul să crească până se compactează singur.
Ordinea permisiunilor: deny → ask → allow

Regulile se evaluează în ordine. Un deny bate mereu orice allow.

1 · deny
refuzată din start, nici măcar nu se cere aprobare
2 · ask
se cere confirmarea ta înainte de execuție
3 · allow
rulează fără să te întrebe
{
  "permissions": {
    "deny": ["Bash(rm -rf *)"],
    "ask":  ["Bash(git push *)"],
    "allow":["Bash(npm run *)"]
  }
}

Fișierul: .claude/settings.json în folderul proiectului. Sintaxa evoluează; confirmă cu /permissions sau /help.

--dangerously-skip-permissions

Sare peste toate confirmările. Acceptabil doar într-un sandbox izolat — niciodată pe cod real sau cu date sensibile.
