# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

This holds Romanian-language training materials for an internal "AI Fluency" program (transitioning a SQL developer team at SSP toward AI-assisted / full-stack development), plus a small static website that publishes the course sessions. There is no build system, package manager, linter, or test suite — none exist and none should be assumed; the site is plain HTML/CSS/JS with zero build step and zero server dependency (open any `.html` file directly in a browser, or serve the directory as-is with any static file server). The directory is now a local git repo (it previously was not).

Content sources:

- [`suport-curs-sesiunea-1.md`](suport-curs-sesiunea-1.md) — facilitator's guide for Session 1 ("Prima zi cu Claude: de la SQL developer la AI-assisted developer"). A run-of-show document: timings, live-demo scripts, copy-paste prompts for exercises, a facilitation notes section ("Note de facilitare — doar pentru Ionut") with pacing/pairing guidance, and an appendix on data-safety rules (Anexa 2 — never send real customer data, connection strings, credentials, or PROD dumps to Claude; the org is in the pharma distribution space). **This facilitator-only content (including the "Note de facilitare" section) must never be copied into any public HTML page** — the public site is a participant-facing derivative, not a republish of the facilitator's guide.
- [`ai-fluency-trainer-kit.html`](ai-fluency-trainer-kit.html) — a single self-contained static HTML page (no external JS deps, Google Fonts only) that is a broader "trainer kit" reference for becoming an AI Fluency trainer/facilitator, built on the Anthropic AI Fluency framework (4D loop: Delegare/Descriere/Discernământ/Diligență) and adult-learning pedagogy. It's a long single-page site with anchor-linked sections (`#framework`, `#drum`, `#curs`, `#nisa`, `#pedagogie`, `#practic`), a light/dark theme toggle, and heavy inline CSS using custom properties for theming. It remains separate trainer-only material — it is not linked from or merged into the participant-facing site below, though its design system (colors, type, theme toggle) was extracted verbatim into `assets/` for reuse there.

The participant-facing site is now a **single-page app shell** ("AI Academy"), rebuilt from a Claude Design handoff (`AI e-learning platform PRD-handoff/`) to match a specific visual/interaction design pixel-for-pixel, then populated with our real course content. It replaced an earlier multi-page version (separate `index.html`/`sesiune-N.html`/`dictionar-ai-engineering.html`/`harta-termeni-ai.html` pages, still visible in git history if needed for reference).

- `index.html` — the single HTML shell: header (brand, breadcrumb, theme toggle), left course sidebar (modules/lessons, glosar/hartă/resurse links), a main content area with 5 view containers (`#view-lesson`, `#view-glossary`, `#view-map`, `#view-onboarding`, `#view-resurse`) that are shown/hidden by JS, and a right TOC sidebar (lesson view only). No server-side routing — everything is one document; JS swaps which view is visible and updates the URL-less in-memory `state.route`.
- `assets/academy.css` — the design system for this app (cream/rust palette, Newsreader/Public Sans/IBM Plex Mono), replicated from the Claude Design mock. **Distinct from and unrelated to** `ai-fluency-trainer-kit.html`'s own design system — the two are visually different on purpose; don't try to unify them.
- `assets/academy-data.js` — all content as plain JS data: `GLOSSARY` (terms + categories), `MODULES` (modules → lessons, each lesson following a fixed template: `intro`, `obiective`, `concept`, `exemplu`, `exercitiuTitle`/`exercitiuText`/`exercitiuPlaceholder`, `recap`), `MAP_NODES`/`MAP_LINES` (the concept-map layout), `RESOURCES` (external links). Editing course content means editing this file, not the HTML.
- `assets/academy.js` — the state manager and renderer: a single `state` object, a `render()` dispatcher that re-renders the sidebar/header/active view on every state change, and one delegated `click` listener reading `data-action`/`data-*` attributes (no per-element `onclick` rebinding, no framework). Adding a new interactive element means adding a `data-action="..."` handler branch in the click listener, not a new function wired by hand.
- **Module/lesson structure is a deliberate restructuring, not a 1:1 port**: the old `sesiune-1.html` (one long page: tutorial 1.1–1.4 + Exercises A–E) became **Module 1** (4 lessons, from the tutorial) + **Module 2** (5 lessons, one per exercise A–E) here, to fit the design's per-lesson template. Modules 3–5 (Agenți, Evaluare, Securitate+Playbook) mirror the previously-decided 4-session plan and are `available:false` placeholders in `MODULES`.
- **The design's "Resurse pentru facilitator" nav item and page were deliberately dropped.** The mock's facilitator-resources route lived in the same public bundle as participant content — exactly what the facilitator-notes-never-public rule (below) exists to prevent. The sidebar's "Resurse recomandate" link points to a genuine participant-facing `resurse` route (external links only, see `RESOURCES` in `academy-data.js`), not a renamed facilitator page.

`excalidraw.log` is a stray MCP server log file, not part of the content — ignore it unless asked to clean it up.

## Working conventions

- **Language**: all course content is Romanian, including the app. Preserve Romanian when editing `suport-curs-sesiunea-1.md` or `assets/academy-data.js`; match existing terminology (e.g. "Delegare/Descriere/Discernământ/Diligență", "sql-enterprise" skill name, `SMT-FAT-SQLB01` / `BufferSap` as the example server/DB) rather than introducing new translations.
- **`ai-fluency-trainer-kit.html` is hand-authored, single-file HTML/CSS** — there's no template engine or bundler. Edit the `<style>` block and markup directly; keep it dependency-free (no new external scripts/CDNs) and keep the light/dark theme working by using the existing CSS custom properties (`--paper`, `--ink`, `--rust`, `--teal`, `--gold`, etc.) rather than hardcoded colors.
- **The AI Academy app (`index.html` + `assets/academy*.{css,js}`) is also hand-authored, no build step.** New course content goes into `MODULES` in `academy-data.js` following the existing lesson shape exactly (all of `intro`/`obiective`/`concept`/`exemplu`/`exercitiuTitle`/`exercitiuText`/`exercitiuPlaceholder`/`recap` — the renderer assumes every field is present). New interactive behavior goes into the single delegated click handler in `academy.js`, not a new inline `onclick`.
- **Facilitator-only content is never public**: anything scoped to the facilitator (pacing notes, internal pairing guidance, the "Note de facilitare" section of `suport-curs-sesiunea-1.md`) stays out of `index.html` and `academy-data.js`. This is why the app has no facilitator route — see above.
- **Data-safety rule referenced throughout the course material** (Anexa 2 in the session doc) also applies to work done in this repo: don't add real customer/patient data, credentials, connection strings, or PROD data dumps into any file here.
- There is no "run" or "preview" command beyond opening `index.html` directly in a browser, or serving the directory with any static file server — no server-side logic is involved either way.
- `AI e-learning platform PRD-handoff/` holds the original Claude Design bundle the app's visual design was implemented from — reference material, not part of the shipped site; don't delete it without checking with the user, but don't treat it as something that needs to stay in sync with `index.html` either.
